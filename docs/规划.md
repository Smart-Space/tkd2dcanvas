# 1. 简介

tkinter 在 Windows 上使用 Direct2D（DirectWrite 负责文字）实现的 Canvas。

---

# 2. 总体架构

```text
Python/tkinter
    |
    v
Tcl interpreter
    |
    v
package require tkd2dcanvas
    |
    v
Tcl command: tkd2dcanvas
    |
    v
C/C++ 实现的 Tk widget
    |
    v
Win32 surface / HWND / WM_PAINT
    |
    v
Direct2D renderer（DirectWrite 负责文字）
    |
    v
Canvas core model
```

Python 用户最终看到的是：

```python
from tkd2dcanvas import Canvas

canvas = Canvas(root, width=800, height=600)
canvas.pack(fill="both", expand=True)

canvas.create_rectangle(20, 20, 200, 120, fill="tomato", outline="navy")
```

底层实际发生的是：

```text
root.tk.call("tkd2dcanvas", pathName, ...)
root.tk.call(pathName, "create", "rectangle", ...)
```

# 3. 推荐项目结构

下面是一个比较适合长期维护的结构。

重点是：

- `native/core` 不依赖 Tcl/Tk，也不依赖 Direct2D。
- `native/render` 依赖 Direct2D / DirectWrite。
- `native/tk_glue` 依赖 Tcl/Tk。
- `tcl/` 是 Tcl package 安装文件。
- `python/` 是 Python 包和兼容层。
- `third_party/tcltk-sdk` 可选，用于放你自己准备的 Tcl/Tk 开发文件。

# 4. 各目录职责说明

---

## 4.1 `native/include/tkd2dcanvas`

这里放核心 C++ 头文件。

原则：

```text
不依赖 Tcl
不依赖 Tk
不依赖 Windows
不依赖 Direct2D
```

例如：

```cpp
class CanvasModel;
class CanvasItem;
class Renderer;
struct BBox;
```

这样你的 Canvas 核心逻辑可以被单独测试。

---

## 4.2 `native/core`

Canvas 的核心模型层。

包括：

```text
item 管理
tag 索引
坐标系
视图窗口
bbox
hit-test
move
scale
delete
z-order
dirty region
```

这层应该是你项目的灵魂。

它不应该知道 Direct2D 是什么，也不应该知道 Tcl/Tk 是什么。

---

## 4.3 `native/items`

各种 Canvas item 类型。

建议先实现：

```text
RectItem
OvalItem
LineItem
TextItem
```

之后再实现：

```text
PolygonItem
ArcItem
ImageItem
BitmapItem
WindowItem
```

其中：

```text
WindowItem
```

最复杂，建议放最后。

---

## 4.4 `native/render`

渲染抽象和 Direct2D 实现。

建议定义一个抽象接口：

```cpp
class Renderer {
public:
    virtual ~Renderer() = default;

    virtual void clear(const Color& color) = 0;

    virtual void drawLine(const Path& path, const PenStyle& pen) = 0;
    virtual void fillPath(const Path& path, const BrushStyle& brush) = 0;

    virtual void drawText(const TextLayout& layout, const TextStyle& style) = 0;
    virtual void drawImage(const ImageRef& image, const Transform2D& transform) = 0;

    virtual void pushClip(const BBox& box) = 0;
    virtual void popClip() = 0;
};
```

然后：

```cpp
class D2DRenderer final : public Renderer {
    ...
};
```

这样以后如果你要换 Direct2D，只需要新增：

```cpp
class D2DRenderer final : public Renderer {
    ...
};
```

这是路线 B 最关键的一层。

它负责把 Tcl/Tk 与你的 C++ Canvas core 粘起来。

实现：

```tcl

```

以及后续：

```tcl
.c create rectangle ...
.c coords ...
.c move ...
.c delete ...
```

创建 Tk widget 窗口，处理：

```text

cget
event handler
```

### `CanvasOptions.cpp`

处理 widget 级选项：

```text
-width
-height
-background
-borderwidth
-highlightthickness
-scrollregion
-xscrollcommand
-yscrollcommand
-xscrollincrement
-yscrollincrement
-closeenough
-confine

```

### `CanvasEventBridge.cpp`

把 Win32/Tk 事件转成 Canvas 事件：

```text
ButtonPress

Motion
Enter
Leave
KeyPress
```

### `CanvasScrollBridge.cpp`

处理滚动：

```text
xview
```

把 Tk 颜色转成内部颜色：


把 Tk font 转成 DirectWrite 可用字体信息。

### `CanvasTkImage.cpp`

### `CanvasTkWindowItem.cpp`

如果要支持：

这里最复杂，建议后期再做。

```text

```



# 6. Python loader 示例

`_loader.py` 可以类似：

```python
from pathlib import Path
import tkinter

_PKG_DIR = Path(__file__).parent
_TCL_PKG_DIR = _PKG_DIR / "tcl"

_loaded = set()


def load_into(master: tkinter.Misc) -> None:
    """
    将 tkd2dcanvas Tcl package 加载到指定 Tk interpreter。
    """
    key = id(master.tk)

    if key in _loaded:
        return

    tcl_dir = _TCL_PKG_DIR.as_posix()

    master.tk.eval(f"lappend auto_path {{{tcl_dir}}}")
    master.tk.call("package", "require", "tkd2dcanvas")

    _loaded.add(key)
```

`__init__.py`：

```python
from ._loader import load_into
from .canvas import Canvas

__all__ = ["Canvas", "load_into"]
```

`canvas.py` 里可以写：

```python
import tkinter

from ._loader import load_into


class Canvas:
    def __init__(self, master=None, **kw):
        load_into(master)

        self._master = master
        self._name = None

        self._create_widget(master, kw)

    def _create_widget(self, master, kw):
        path = f"{master._w}.tkd2dcanvas_{id(self)}"

        args = ["tkd2dcanvas", path]

        for key, value in kw.items():
            args.append(f"-{key}")
            args.append(value)

        master.tk.call(*args)

        self._name = path

    def create_rectangle(self, *args, **kw):
        cmd = [self._name, "create", "rectangle", *args]

        for key, value in kw.items():
            cmd.append(f"-{key}")
            cmd.append(value)

        return self._master.tk.call(*cmd)

    def coords(self, *args):
        return self._master.tk.call(self._name, "coords", *args)

    def move(self, *args):
        return self._master.tk.call(self._name, "move", *args)

    def delete(self, *args):
        return self._master.tk.call(self._name, "delete", *args)
```

真正产品化时，还需要处理：

- 选项序列化。
- Tcl list 转换。
- 返回值解析。
- 事件绑定。
- `pack/grid/place` 代理。
- `winfo` 兼容。
- 销毁逻辑。

# 7. Tcl package 入口示例

路线 B 的 C/C++ 扩展入口大致是：

```cpp
#include <tcl.h>
#include <tk.h>

#include <windows.h>
#include <d2d1.h>
#include <dwrite.h>

static int
Tkd2dcanvasCmd(
    ClientData clientData,
    Tcl_Interp* interp,
    int objc,
    Tcl_Obj* const objv[])
{
    // 创建或分发 canvas widget 命令
    return TCL_OK;
}

extern "C"
__declspec(dllexport)
int Tkd2dcanvas_Init(Tcl_Interp* interp)
{
    if (Tcl_InitStubs(interp, "8.6", 0) == nullptr) {
        return TCL_ERROR;
    }

    if (Tk_InitStubs(interp, "8.6", 0) == nullptr) {
        return TCL_ERROR;
    }

    Tcl_CreateObjCommand(
        interp,
        "tkd2dcanvas",
        Tkd2dcanvasCmd,
        nullptr,
        nullptr
    );

    Tcl_PkgProvide(interp, "tkd2dcanvas", "0.1");

    return TCL_OK;
}
```

注意：

- 包名建议小写：`tkd2dcanvas`。
- 初始化函数名通常是：`Tkd2dcanvas_Init`。
- 如果你要支持 safe interpreter，可以再加：

```cpp
extern "C"
__declspec(dllexport)
int Tkd2dcanvas_SafeInit(Tcl_Interp* interp)
{
    return TCL_ERROR; // 或实现安全版本
}
```

一开始可以不支持 safe。

# 9. 构建产物应该长什么样？

路线 B 的核心构建产物是 Tcl package：

```text
tkd2dcanvas/
├── pkgIndex.tcl
└── tkd2dcanvas01.dll
```

而不是普通 Python `.pyd`。

这一点很重要。

路线 B 的原生产物不是给 Python 直接 `import` 的 `.pyd`，而是给 Tcl `package require` 加载的 DLL。

Python 包只是负责：

```text
找到这个 Tcl package
```

# 11. 运行时加载流程

用户代码：

```python
import tkinter
import tkd2dcanvas

root = tkinter.Tk()

tkd2dcanvas.load_into(root)

canvas = tkd2dcanvas.Canvas(root, width=640, height=480)
canvas.pack(fill="both", expand=True)

canvas.create_rectangle(20, 20, 200, 120, fill="tomato")

root.mainloop()
```

内部流程：

```text
1. import tkd2dcanvas
2. load_into(root)
3. lappend auto_path .../site-packages/tkd2dcanvas/tcl
4. package require tkd2dcanvas
5. Tcl 加载 tkd2dcanvas01.dll
6. 调用 Tkd2dcanvas_Init
7. 注册 Tcl command: tkd2dcanvas
8. Python 调用:
   tkd2dcanvas .c -width 640 -height 480
9. C/C++ 创建 Tk widget
10. Python 调用:
    .c create rectangle ...
11. C/C++ 更新 CanvasModel
12. Win32 surface invalidate
13. WM_PAINT
14. D2DRenderer 绘制
```

# 13. 路线 B 的关键技术风险

---

## 13.1 Tcl/Tk dev 文件缺失

这是第一道门槛。

你需要尽早确认：

```text
有没有 tcl.h
有没有 tk.h
有没有 tclstub*.lib
有没有 tkstub*.lib
版本是否匹配
编译器是否匹配
```

建议先写一个工具：

```text
tools/check_tcltk_dev.py
```

检查：

```text
include path
lib path
stub libs
TCL version
TK version
compiler compatibility
```

---

## 13.2 Python 的 Tcl/Tk 版本和你编译用的版本不一致

例如：

```text
Python tkinter: Tcl/Tk 8.6
你编译扩展:     Tcl/Tk 9.0
```

这可能导致：

```text
package require 失败
API 不存在
行为变化
stub 版本不兼容
```

建议：

> 第一版只支持 Python 当前使用的那个 Tcl/Tk major.minor。

---

## 13.3 MSVC / MinGW ABI 问题

如果你用 python.org 的 Windows Python：

```text
Python 本体和 _tkinter.pyd 通常是 MSVC 构建的
```

你的 Tcl 扩展最好也用：

```text
MSVC
```

虽然 Tcl package 是 C ABI DLL，理论上不一定强绑编译器，但为了避免奇怪问题，推荐：

```text
Visual Studio / MSVC 工具链
```

如果你用 MSYS2 MinGW Python，则可以考虑 MinGW。

---

## 13.4 Tk 窗口绘制模型

Tk 本身在 Windows 下有自己的窗口过程和绘制流程。

你要用 Direct2D 绘制，需要验证：

```text
能否可靠拿到 HWND
能否正确处理 WM_PAINT
能否正确响应 resize
能否正确裁剪
能否避免闪烁
能否与 Tk 事件循环协作
```

建议一开始做一个 spike：

```text
创建空 Tk widget
在其窗口区域用 Direct2D 画一个红色矩形
缩放窗口时不闪烁
```

如果这个跑不通，后面都白搭。

---

## 13.5 事件桥接

如果你的 Direct2D surface 是 Tk window 下面的子 HWND，那么鼠标键盘事件可能先进入子 HWND。

你需要决定：

```text
是在 Win32 层处理？
还是转发到 Tk 事件？
还是直接在 C/C++ 中实现 canvas binding？
```

推荐：

> Canvas 自己的 `bind`、`tag_bind`、`current`、`focus` 逻辑由你的 C++ core 管理。  
> 不要把所有东西都塞回标准 Tk 事件。

但基础窗口事件仍然要和 Tk 协调，比如：

```text
FocusIn/FocusOut
Enter/Leave
TakeFocus
keyboard traversal
```

---

## 13.6 `create_window` 很难

`create_window` 涉及真实 Tk 子窗口。

# 14. 推荐的最终目录职责总表

| 目录                            | 作用                            | 依赖               |
| ------------------------------- | ------------------------------- | ------------------ |
